# HTTP и HTTPS

HTTP (HyperText Transfer Protocol) — протокол прикладного уровня для обмена данными между клиентом и сервером. HTTPS — тот же HTTP поверх шифрования TLS.

---

## Жизненный цикл запроса

1. **DNS** — разрешение домена в IP-адрес
2. **TCP** — установка соединения (three-way handshake)
3. **TLS** (для HTTPS) — обмен ключами, шифрование
4. **HTTP-запрос** — метод, путь, заголовки, тело
5. **HTTP-ответ** — статус, заголовки, тело
6. **Закрытие соединения** или переиспользование (keep-alive / пул соединений)

Подробнее о навигации и сетевом стеке: [Как работает браузер](./how-browsers-work).

Структура запроса (упрощённо):

```http
GET /api/users?active=1 HTTP/1.1
Host: api.example.com
Accept: application/json
Authorization: Bearer <token>
```

## Методы HTTP

| Метод | Назначение | Идемпотентность | Обычно с телом |
|-------|------------|-----------------|----------------|
| GET | Получение ресурса | Да | Нет |
| POST | Создание / действие | Нет | Да |
| PUT | Полная замена | Да | Да |
| PATCH | Частичное обновление | Нет* | Да |
| DELETE | Удаление | Да | Редко |
| HEAD | Только заголовки | Да | Нет |
| OPTIONS | Мета / CORS preflight | Да | Нет |

**Идемпотентность** — повтор того же запроса даёт тот же эффект на сервере (не обязательно тот же байтовый ответ). `GET` безопасен (не должен менять состояние). `POST` повтор может создать дубликаты — на практике часто добавляют ключ идемпотентности. См. [Идемпотентность](../systedesign/idempotency).

\*PATCH по спецификации не обязан быть идемпотентным; зависит от семантики API.

## Коды статуса

| Класс | Примеры | Смысл |
|-------|---------|--------|
| **2xx** | `200 OK`, `201 Created`, `204 No Content` | Успех |
| **3xx** | `301`, `302`, `304 Not Modified` | Редирект / взять из кэша |
| **4xx** | `400`, `401`, `403`, `404`, `409`, `429` | Ошибка клиента |
| **5xx** | `500`, `502`, `503`, `504` | Ошибка сервера / шлюза |

Частые на собеседовании:

- `401` — не аутентифицирован; `403` — аутентифицирован, но нельзя
- `304` — условный запрос, тело не нужно (кэш валиден)
- `429` — rate limit

## Важные заголовки

**Запрос:**

- `Host` — целевой хост
- `Authorization` — токен / Basic auth
- `Content-Type` — тип тела (`application/json`)
- `Accept` — ожидаемый формат ответа
- `Cookie` — куки клиента
- `If-None-Match` / `If-Modified-Since` — условные запросы к кэшу
- `Origin` — для CORS

**Ответ:**

- `Content-Type`, `Set-Cookie`, `Location` (редирект)
- `Cache-Control`, `ETag`, `Last-Modified`, `Vary`
- `Access-Control-*` — см. [CORS](./cors)

## Кеширование (HTTP cache)

Браузер / CDN решают, можно ли отдать ответ без сети:

```http
Cache-Control: max-age=3600, public
ETag: "abc123"
```

| Механизм | Идея |
|----------|------|
| `Cache-Control: max-age` | Свежесть в секундах |
| `no-store` / `no-cache` | Не сохранять / всегда ревалидировать |
| `ETag` + `If-None-Match` | «Изменилось ли?» → часто `304` |
| `Last-Modified` + `If-Modified-Since` | То же по времени |
| `Vary: Accept-Encoding` | Разные представления в кэше |

Для SPA API часто `Cache-Control: no-store` на персональные данные; статика — длинный `max-age` + хэш в имени файла.

Подробнее на уровне архитектуры: [Стратегии кэширования](../systedesign/caching-strategies), [CDN](../systedesign/cdn).

## HTTPS и TLS

HTTPS защищает:

- **Конфиденциальность** — данные зашифрованы
- **Целостность** — данные не изменены по пути
- **Аутентичность** — сертификат подтверждает домен

TLS handshake (упрощённо): ClientHello → ServerHello + сертификат → обмен ключами → зашифрованный HTTP.

## HTTP/2 и HTTP/3 (кратко)

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
|--|----------|--------|--------|
| Транспорт | TCP, часто много соединений | Один TCP, мультиплекс потоков | QUIC (UDP) |
| Head-of-line | На уровне запросов (pipeline) | На уровне TCP | Потоки независимее |
| Заголовки | Текст каждый раз | HPACK-сжатие | QPACK |
| Шифрование | Опционально (HTTPS) | На практике почти всегда TLS | Встроено в QUIC |

Семантика методов и статусов та же — меняется доставка.
