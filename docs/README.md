# Документация (VitePress)

Сайт документации собирается через VitePress и деплоится на GitHub Pages.

Запуск локально: `yarn dev:docs` (алиас: `yarn docs`). Сборка: `yarn build:docs`.

> **Примечание:** папка `systedesign/` — legacy-имя (опечатка от systemdesign). URL `/systedesign/` сохранён для обратной совместимости с GitHub Pages.

## Шаблон для index-страницы раздела

При добавлении или правке раздела придерживайтесь единой структуры `index.md`:

1. **Заголовок (H1)** — название раздела.
2. **Краткое описание** — 1–2 предложения, о чём раздел.
3. **Содержание** — блок `## 📚 Содержание` с подзаголовками по темам и ссылками на статьи.
4. **Связанные разделы** (по желанию) — блок `## 🔗 Связанные разделы` со ссылками на смежные разделы.
5. В конце — ссылка «Вернуться к главной документации».

Для разделов с большим числом статей (например, системный дизайн) можно группировать содержание по подтемам (Основы, Базы данных, Масштабирование и т.д.).

**Emoji:** в index-страницах используйте только 📚 (содержание) и 🔗 (связанные разделы). В статьях emoji в заголовках не используются.

## Шаблон для статьи

```markdown
---
title: Название
description: Краткое описание для SEO
---

# Название темы

Краткое введение (1–2 предложения).

## Основной контент

...

## Связанные материалы

- [Смежная статья](./other)
- [Решение в репозитории](https://github.com/dmitryshelomanov/tasks-solutions/blob/main/src/...)
```

**Соглашения:**

- Каждая статья начинается с **H1**.
- Язык code fence: `javascript` или `typescript` (не `js` / `ts`).
- Навигация prev/next — только в разделе системного дизайна (последовательный «курс»). В остальных разделах — sidebar.
- Разделитель `---` в теле статьи — горизонтальная линия, не frontmatter.

## Добавление новой страницы

При добавлении нового `.md` файла в раздел:

1. **Создать файл** с H1 и frontmatter (`title`, `description`).
2. **Обновить sidebar** в `docs/.vitepress/config.mts`: добавить пункт в массив `items` нужного раздела в `themeConfig.sidebar`.
3. **Обновить index раздела** — добавить ссылку на новую статью в блок «Содержание».
4. **Добавить кросс-ссылки** на смежные статьи и код в `src/`, если есть.
5. **Проверить сборку:** `yarn build:docs`.
