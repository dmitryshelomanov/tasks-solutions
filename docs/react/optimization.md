# Оптимизация React

React достаточно быстр «из коробки». Преждевременная мемоизация усложняет код без выигрыша. Оптимизируйте, когда есть измеримая проблема (медленный рендер, INP).

---

## React.memo

Оборачивает компонент и пропускает ре-рендер, если props не изменились (поверхностное сравнение).

```javascript
const ExpensiveList = React.memo(function ExpensiveList({ items }) {
  return items.map((item) => <Row key={item.id} {...item} />);
});
```

**Когда использовать:**

- Компонент рендерится часто с теми же props
- Рендер дорогой (большой список, тяжёлые вычисления в JSX)

**Когда не нужен / бесполезен:**

- Props меняются каждый рендер (новые объекты/функции с родителя)
- Компонент дешёвый — сравнение props может стоить дороже рендера
- Дети всё равно часто обновляются из Context

```javascript
// memo бесполезен: onClick — новая функция каждый раз
<ExpensiveList items={items} onClick={() => doSomething()} />
```

Стабилизируйте колбэк (`useCallback`) или не передавайте инлайн, если цель — сработавший `memo`.

## useMemo

Кэширует **результат вычисления** между рендерами.

```javascript
const sorted = useMemo(
  () => items.slice().sort((a, b) => a.name.localeCompare(b.name)),
  [items]
);
```

**Когда использовать:**

- Дорогие вычисления (фильтрация тысяч элементов)
- Стабильная ссылка на объект/массив для deps дочерних `useEffect` / `memo`

**Когда не нужен:**

- Простые операции (`a + b`, `items.length`)
- «На всякий случай» — шум в deps и риск устаревших значений при забытой зависимости

---

## useCallback

Кэширует **функцию** между рендерами.

```javascript
const handleClick = useCallback((id) => {
  setSelected(id);
}, []);
```

**Когда использовать:**

- Функция передаётся в `memo`-компонент
- Функция — зависимость `useEffect`

**Когда не нужен:**

- Дочерний компонент не мемоизирован
- Создание функции дешевле, чем сравнение зависимостей

## Антипаттерны

| Антипаттерн | Почему плохо |
|-------------|--------------|
| `memo` на всём подряд | Шум, хрупкие deps, ложное чувство скорости |
| `useMemo(() => ({ ... }), [])` «чтобы не ре-рендерить» | Не чинит ре-рендер родителя; чинит только ссылку |
| Новые `style={{}}` / `value={{}}` в Context | Срывает memo и всех consumers |
| Оптимизация до измерения | Тратите время не на узкое место |
| Гигантский компонент + точечный memo | Лучше сначала разбить дерево |

---

## Другие приёмы

| Приём | Эффект |
|-------|--------|
| Code splitting (`React.lazy`) | Меньше JS на старте |
| Виртуализация списков | Рендер только видимых строк |
| Стабильные `key` в списках | Корректный diffing, меньше remount |
| `useTransition` | Неблокирующие обновления UI |
| `useDeferredValue` | Отложенное отображение тяжёлого контента |
| Разделение Context | Меньше лишних подписчиков |

---

## React Compiler

Если в проекте включён React Compiler, он автоматически мемоизирует вычисления и компонентов где безопасно. Ручные `useMemo`/`useCallback` тогда нужны реже — пишите идиоматичный код, оставляйте ручную мемоизацию для явных граничных случаев и библиотек без compiler.

---

## Чеклист перед оптимизацией

1. Измерьте (React DevTools Profiler, Lighthouse INP)
2. Найдите узкое место (какой компонент, какой рендер, почему)
3. Примените минимальное решение (часто — стабильный key, меньше context value churn, виртуализация)
4. Перемерьте
