# Rate Limiting

Rate limiting ограничивает количество запросов от клиента за период времени. Защищает от злоупотреблений, DDoS и перегрузки backend.

---

## Зачем нужен

- **Защита API** — предотвращение brute-force, scraping
- **Справедливое распределение** — один клиент не монополизирует ресурсы
- **Соблюдение SLA** — тарифные планы (1000 req/min для free tier)
- **Стабильность** — предсказуемая нагрузка на БД

---

## Алгоритмы

### Fixed Window

Счётчик сбрасывается каждые N секунд.

- Просто реализовать
- Проблема «burst на границе окна» (2× лимит за 1 с на стыке)

### Sliding Window

Учитывает запросы за последние N секунд (скользящее окно).

- Точнее, чем fixed window
- Больше памяти (хранить timestamps)

### Token Bucket

Ведро с токенами: каждый запрос забирает токен; токены пополняются с фиксированной скоростью.

- Допускает кратковременные всплески (burst)
- Гибкий и популярный

### Leaky Bucket

Запросы «утекают» с фиксированной скоростью — сглаживает трафик.

---

## Реализация

**Где ставить:**
- API Gateway / Load Balancer (Nginx, Kong, AWS API Gateway)
- Middleware приложения
- Redis (счётчики с TTL) — для распределённых систем

```text
Ключ: rate_limit:{user_id}:{endpoint}
Значение: счётчик
TTL: окно (например, 60 с)
```

---

## HTTP-заголовки

Клиенту сообщают лимиты через заголовки:

```http
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 42
X-RateLimit-Reset: 1719763200
```

При превышении: **429 Too Many Requests** + `Retry-After`.
